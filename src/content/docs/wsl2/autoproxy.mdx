### 问题

在使用 WSL 时，经常会遇到如下提示：

> *wsl: 检测到 localhost 代理配置，但未镜像到 WSL。NAT 模式下的 WSL 不支持 localhost 代理。*

此时 WSL 无法使用宿主机的代理设置，通常需要启用 TUN 模式才能让其访问。然而，TUN 模式同时也代理了所有程序的网络请求，使得很多直连的场景也使用代理访问。

### 解决方案

1. 打开 WSL Settings 应用，将“已启用自动代理”**设置为关**。
2. 在 WSL 中修改 `~/.bashrc`，在尾部添加如下代码：

```bash
BASE_PS1="$PS1"

sp() {
  local host="$(ip route show | grep -i default | awk '{ print $3 }')"
  local ports=(7890) # 数组，可以更改为多个可能的端口

  for port in "${ports[@]}"; do
    if timeout 0.1 bash -c "echo >/dev/tcp/$host/$port" > /dev/null; then
      export http_proxy="http://$host:$port"
      export https_proxy="http://$host:$port"
      export no_proxy="localhost,127.0.0.1"
      PS1="(proxy) $BASE_PS1"
      return 0
    fi
  done
  unset http_proxy
  unset https_proxy
  unset no_proxy
  PS1="$BASE_PS1"
}

sp
```

这个脚本的本质是：**放弃让 WSL 自动同步 Windows 的代理设置**，改为在每次打开终端时，自己"敲门"试探 Windows 上的代理端口是否活着，活着就挂上，死了就清空，全程不依赖 WSL 的代理检测机制。
